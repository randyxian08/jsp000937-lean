# Reproducing this review

Use a fresh audit directory. Keep the checking container unprivileged and do not mount credentials, your home, or the Docker socket. The report records the observed image/compiler hashes and platform; a future Debian package installation is not claimed to be bit-identical.

1. Clone `https://github.com/randyxian08/jsp000937-lean` and detach at `c6819617f4d8de6afcbf63da31544ce2902f7b6a`. Do not use cached custom proof `.olean` files or modify its pins.
2. Build the supplied `Dockerfile.base`. Obtain and extract `https://releases.lean-lang.org/lean4/v4.33.0/lean-4.33.0-linux_aarch64.tar.zst`; compare its SHA-256 to `f961a417cba10b6ea0a9d136712d5952813817ffd6680041f09a233526f803a9`. This run used uid/gid 10001, 3 CPUs, a 6 GiB configured memory limit, pid limit 512, and no-new-privileges.
3. In a new container, expose the cloned source at `/project`, the read-only extracted toolchain at `/opt/lean`, an initially empty writable `/logs`, and a writable `/audit` containing only `targets.json`, `Specification.lean.txt`, `Review937.lean.txt`, `run-checks-low-memory.sh`. Do not copy the published historical `check-01`/`preflight-01` directories into the new `/audit`, because the helper requires fresh output paths. Put `tool/audit.py.txt` at the read-only path `/tool/scripts/audit.py` (without changing its content). Set `HOME=/work` and `PATH=/opt/lean/bin:/usr/local/bin:/usr/bin:/bin`.
4. Set Git's safe directory only inside the container if needed: `git config --global --add safe.directory /project`. In `/project`, run `/opt/lean/bin/lake exe cache get` with network access, retain its log and confirm every package checkout against the original manifest. Disconnect the container's network before the next commands.
5. In `/project`, run `/opt/lean/bin/lake build` on the untouched source. Retain stdout/stderr and exit code. Build the supporting import with `/opt/lean/bin/lake build +Erdos1153.JSPInterpolation.JSP958`; this is required only because `AuditFull.lean` also checks that included library result.
6. Run `sh /audit/run-checks-low-memory.sh` and retain its exit code. It copies the additional audit modules, builds their explicit module, runs official preflight and all 8 target/source/axiom checks, both original audit files and the final module's Lean kernel replay. The original source should have no tracked diff; only the two audit `.lean` files should be untracked. Hashes and logs of the published run are supplied for comparison.

The original project's own `bash verify.sh` is a separate direct reproduction route for its submitted library/audit/replay checks. The new formula specification and bridges are additional review artifacts and are not part of the pinned proof A. Successful checking does not establish independent identity, priority or prize eligibility.

The original default-parallel replay was killed by OOM after all earlier checks passed. The supplied low-memory variant caps replay workers with `LEAN_NUM_THREADS=1`; the verified retry used this environment without changing any source or checker criteria. See the report and retry log for actual commands.
